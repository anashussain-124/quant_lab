# Quant Research Lab — Obsidian Workflow

## One-time setup

The verified vault path is configured in `configs/obsidian_sync.json` as
`C:\Users\<USER>\Documents\Obsidian Vault`. If the vault is moved, update
`vault_path`. Result, registry, and data paths are resolved relative to the
project root unless configured as absolute paths. No Obsidian API, account,
cloud service, or network access is used.

From PowerShell in the project root:

```powershell
qt\.venv\Scripts\python.exe -m scripts.obsidian_sync --help
qt\.venv\Scripts\python.exe -m scripts.obsidian_sync inspect
qt\.venv\Scripts\python.exe -m scripts.obsidian_sync sync
```

`sync` creates missing folders and curated notes without moving or deleting
existing notes. It imports configured JSON/JSONL/CSV artifacts into
`07 Results & Reports/Generated by Quant Lab`, writes a stable ID map beside
the generated notes, and updates only marked sections in the existing
dashboard, experiment registry, and data-quality note. Manually authored
content outside the markers remains untouched. If source data is malformed,
the command reports the error and creates/updates `Import Issues.md`; fix the
source/configuration and rerun.

## Daily research loop

1. Start with [[Quant Research Dashboard]] and check environment labels.
2. Reproduce the existing baseline using only the documented project commands
   and pre-registered inputs. Do not run the holdout command until its protocol
   permits one-time access and the access is authorized.
3. Validate market data before any backtest:

   ```powershell
   qt\.venv\Scripts\python.exe -m scripts.obsidian_sync validate
   ```

   Or specify explicit CSV/Parquet paths after `validate`. The validator is
   read-only; it does not repair data. It reports gaps but does not automatically
   treat market closures as corruption.
4. Record a new hypothesis, trial budget, frozen parameters, success criteria,
   environment, data hash, and expected costs before running it.
5. Run an existing research entry point only after confirming its `--help`,
   cost, and holdout behavior. This integration does not launch backtests.
6. Add actual completed outputs to `result_paths` or JSONL ledgers to
   `registry_paths` in the config. Supported formats are JSON campaign reports,
   append-only JSONL records, and the existing cost-decomposition CSV schema.
7. Regenerate local notes:

   ```powershell
   qt\.venv\Scripts\python.exe -m scripts.obsidian_sync report
   qt\.venv\Scripts\python.exe -m scripts.obsidian_sync sync
   qt\.venv\Scripts\python.exe -m scripts.obsidian_sync list
   ```

8. Review each generated experiment note and record human interpretation,
   limitations, and the next action in [[Research Decision Log]]. Generated
   result notes are not manually edited because the next sync refreshes them;
   put human conclusions in the linked manual notes.
9. Complete [[Validation Checklist]] before considering a candidate. A completed
   backtest is not a validated strategy. The safe outcome may be `NO_TRADE`.

## Configuration

`configs/obsidian_sync.json` controls:

- `vault_path`: actual local vault path.
- `project_root`: base directory for relative paths.
- `generated_notes_dir`: generated-only subdirectory inside the vault.
- `result_paths`: JSON report and CSV result artifacts.
- `registry_paths`: append-only JSONL experiment records.
- `metadata_paths`: optional append-only JSONL pre-registration and status
  records. Keep each record on its original line so its stable source key and
  generated `EXP-###` ID do not change. A record may use `Planned`, `Running`,
  `Completed`, `Failed`, `Needs Review`, `Rejected`, `Candidate for Validation`,
  or `Validated`; a status label is not itself evidence of passing a gate.
- `data_paths`: local CSV/Parquet candle files for read-only validation.
- `report_inclusion`: whether to emit individual trial notes and research summary.
- `minimum_data_quality_score`: integrity threshold (0–1).

An optional metadata JSONL record can include the following fields; missing
values remain explicit `Unknown`/`Not Available` in generated notes:

```json
{"status":"Planned","created_at_utc":"2026-10-26T00:00:00+00:00","strategy":"Example hypothesis","strategy_version":"1","git_commit":"<commit>","dataset_id":"<sha256>","date_range":"<UTC start> to <UTC end>","instrument":"XAUUSD","timeframe":"H1","parameters":{"lookback":20},"backtest_command":"<actual command>","engine_version":"<version>","cost_assumptions":{"spread":"<value or model>","commission":"<value or model>","slippage":"<value or model>"},"environment":"BACKTEST","data_environment":"HISTORICAL_REAL","result_path":"<path or Not Available>","metrics":{},"interpretation":"Pre-register hypothesis and success criteria.","next_action":"Run only after human approval."}
```

Add metadata files to `metadata_paths` before synchronization. Do not reuse or
reorder records; IDs are reserved across existing vault notes and project
records and persisted in the generated ID map.

Missing metadata stays `Unknown` or `Not Available`. Check [[FundingPips Risk
Rules]] for profile values and unresolved official-rule details; values in the
local profile were last recorded as verified on 2026-10-22 and must be checked
against current authoritative terms before any reliance.

## What is real, simulated, and unverified

- **Real:** local source files and recorded historical market-data artifacts;
  hashes, parameters, and metrics are copied from their source records.
- **Simulated:** all backtest/trade metrics and any demo/paper result; they are
  not live fills or evidence of live viability.
- **Unverified:** fields absent from source records, current FundingPips rules
  not rechecked on the official site, and any strategy not supported by a
  passing validation record.
- **Could invalidate conclusions:** data revisions, incorrect timezone/session
  alignment, omitted or misestimated costs, selection bias, execution model
  mismatch, and market-structure changes.
